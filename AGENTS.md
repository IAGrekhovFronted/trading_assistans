# Сопровождение «Точки входа»

Инструкции относятся к приложению в этой папке. Начальная точка — [README.md](README.md).
Документация сверена с реализацией 2026-11-08; при изменении поведения обновлять её вместе с кодом.

## Ориентирование

1. Прочитать [архитектуру](docs/ARCHITECTURE.md).
2. Перед изменением сохранения, схем или импорта прочитать [модели данных](docs/DATA.md).
3. Запуск, проверки и ограничения — в [руководстве разработки](docs/DEVELOPMENT.md).
4. Существенные решения фиксировать в документации, чтобы поддержка не зависела от истории чата.

## Устройство проекта

- Vanilla JavaScript ESM, HTML/CSS, встроенные модули Node; без сборщика и сторонних пакетов.
- `server.mjs` — статический сервер, а не API сохранения.
- `app.mjs` — интерфейс, состояние, автосохранение, журнал и импорт/экспорт.
- `engine.mjs` — встроенный алгоритм, адаптеры маршрутов, фиксация решения и расчёты.
- `schemes.mjs` — формат, проверка и выполнение пользовательских схем.
- `builder.mjs` — редактор и карта переходов.
- `storage.mjs` — IndexedDB. Пользовательские данные находятся в браузере, вне исходников.

## Контракты поведения

- Рабочий адрес — `http://127.0.0.1:4666`. Смена origin открывает другое хранилище.
- Не пересоздавать IndexedDB ради обновления. Изменение формата требует совместимости
  или миграции с сохранением данных.
- Снимок схемы создаётся при запуске разбора. Правки/удаление схемы из библиотеки
  не должны менять старые разборы, включая незавершённые.
- Статус схемы `draft` не равен ошибке в графе: корректная схема тоже может быть черновиком.
  Сохранять незаполненные переходы и `editorNodeId`; готовность задаётся явным действием пользователя.
- После фиксации решения ответы заблокированы; исход, суммы, комментарии и изображения
  заполняются отдельно. Основания решения не заменяются сведениями, появившимися после сделки.
- Изменение раннего ответа в черновике удаляет последующие ответы.
- `matched` — категория отмеченных условий, не команда совершить сделку.
- Винрейт: `win / (win + loss)`. Возвраты, ожидание и наблюдения исключены из знаменателя.
  Полная выплата включает ставку; прибыль равна выплате минус ставка.
- Текущие критерии не используют BB/SMA20. Не менять торговые условия под видом исправления UI.
- Пользовательский текст экранировать при HTML/SVG-рендеринге; импорт проверять до записи.

## Внесение изменений

- UI находится в `app.mjs`, `builder.mjs`, `styles.css`; чистая логика — в engine/schemes.
- Для работы с произвольной сессией использовать `routeFor`, `answerFor`, `evaluationFor`, `scenarioFor`.
  Прямые `route(answers)` и `evaluation(answers)` обслуживают только встроенный алгоритм.
- Новый браузерный модуль включать в allowlist `server.mjs`. После изменения allowlist нужен перезапуск.
- Сохранять UTF-8 с BOM у `Start.ps1` и `Stop.ps1`: они также запускаются Windows PowerShell 5.
- Сторонние зависимости добавлять только при конкретной необходимости задачи.
- Пользовательские записи и тексты схем не отправлять во внешние сервисы при сопровождении.

## Проверка и передача

- `npm test` запускает все тесты Node. Изменения логики проверять существенными поведенческими тестами.
- Вёрстку проверять в браузере при широком и узком окне. После проверки снимать временный viewport override.
- Синтетические записи создавать на порту 4668; рабочий журнал на 4666 не засорять тестовыми сделками.
- Если затронуты хранение/схемы/импорт, проверить перезагрузку, старые снимки и JSON round-trip.
- Останавливать только свой проверочный сервер, а не все процессы Node. Сервер 4666 нужен пользователю.
- В отчёте назвать изменения, реально выполненные проверки и существенные ограничения.
  Для правок только документации достаточно проверки документов и ссылок.
