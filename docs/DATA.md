# Данные и совместимость

## Физическое хранение

IndexedDB: `entry-navigator-local`, версия БД **1**. Реализация — `storage.mjs`.

| Object store | Ключ | Содержимое |
| --- | --- | --- |
| `sessions` | `id` через keyPath | Разбор со всеми полями, исходом и изображениями |
| `meta` | Явный строковый ключ | `currentId`: текущий разбор; `schemes`: библиотека; `hiddenBuiltinExamples`: скрытые ID встроенных примеров |

Хранилище относится к origin и профилю браузера. Перезапуск сервера сохраняет БД.
Перенос исходников, смена браузера, имени хоста или порта не переносит IndexedDB.
За квоту и сохранение на диске отвечает браузер; persistent-storage API приложение не вызывает.
Очистка данных сайта удалит БД.

`.runtime/` содержит PID и логи сервера, а не журнал. `*-preview.jpg` и `qa-schemes.jpg`
в папке исходников — артефакты проверки UI, а не архив пользовательских изображений.

## Разбор — session

| Поле | Значение |
| --- | --- |
| `id` | Стабильный ID; создаётся через `crypto.randomUUID()` |
| `createdAt`, `updatedAt` | ISO-строки времени |
| `algorithmVersion` | `0.1` для встроенного маршрута; `custom.<revision>` для своей схемы |
| `symbol`, `expiryMinutes` | Инструмент и экспирация; по умолчанию `BTC/USDT` и `5` |
| `answers` | Объект: ключ вопроса → выбранное значение ответа |
| `cursor` | Необязательный индекс экрана, начиная с 0 |
| `zone`, `zoneStrength` | Текст зоны; `unknown`, `strong` или `ordinary` из UI |
| `notes` | Комментарий пользователя |
| `screenshots` | Массив `{name, data}`, где `data` — base64 data URL |
| `disposition` | `draft`, `trade` или `observation` |
| `trade` | Фактические параметры сделки |
| `schemeId`, `schemeSnapshot` | Для своей схемы: ID библиотеки и полная глубокая копия схемы |
| `decisionSnapshot` | Появляется при фиксации решения |

`trade`: `executed` (boolean), `outcome` (`pending`, `win`, `loss`, `draw`), `entryTime`,
`entryPrice`, `exitPrice`, `stake`, `payout`.
Числовые поля формы хранятся строками. Пустая строка — отсутствие значения, а не ноль.
`decimal` принимает точку/запятую и удаляет пробелы.
`entryTime` соответствует `datetime-local` и не содержит часового пояса.
Служебные `createdAt` и `decisionSnapshot.at` содержат ISO-время.

`decisionSnapshot`: `{answers, algorithmVersion, conclusion, at}`.
`conclusion`: `kind`, `title`, `reason`, `code`; у встроенного маршрута также может быть `experimental`.
После фиксации снимок ответов должен совпадать с `session.answers`.

Встроенные ключи ответов: `global`, `wave`, `correction`, `local`, `pullback`, `level`,
`stoch`, `reaction`, `confirmation`. Допустимые значения определены в `question` из `engine.mjs`.
В своей схеме ключ ответа — ID блока, значение — ID варианта ответа из этого блока.

## Удаление разбора

`repository.removeRecord(id, nextCurrentId)` удаляет объект из `sessions` вместе со скриншотами
и снимком схемы и обновляет `meta.currentId` одной readwrite-транзакцией по двум stores.
Ошибка откатывает транзакцию. Если записей больше нет, `currentId` равен `null`.
Пустая БД не заполняется черновиком при обычной загрузке. Версия БД и stores не меняются.
Корзины нет; восстановление возможно из ранее сохранённого JSON по правилам импорта.

## Пользовательская схема

Форма объекта схемы:

```js
{
  id, name, description, revision, createdAt, updatedAt,
  status, // draft | ready; поле необязательно для старых архивов
  editorNodeId, // необязательный ID последнего открытого блока
  startId, // ID стартового вопроса
  nodes: [/* блоки question и result */]
}
```

Блок вопроса:

```js
{
  id, type: 'question', title, hint,
  hintImages, // необязательно: [{id, name, data}]
  options: [{id, label, next, exampleImages}] // exampleImages: [{id, name, data}]
  // next — ID следующего вопроса либо итога
}
```

Итоговый блок:

```js
{id, type: 'result', title, description, kind}
// kind: matched | waiting | unclear
```

Выше обозначения полей, а не готовый JSON для импорта. Корректные объекты создают
`newScheme()` и `templateScheme()` в `schemes.mjs`.

ID блоков уникальны внутри схемы, ID ответов — внутри вопроса.
Разрешены буквы ASCII, цифры, `_` и `-`; запрещены `__proto__`, `constructor`, `prototype`.
Старт должен быть вопросом. У вопроса минимум два ответа с разными непустыми названиями.
Каждый ответ ведёт в существующий блок. Достижимые циклы блокируют запуск.
Недостижимые блоки дают предупреждение и не участвуют в пути.

`assertSchemeShape` проверяет структуру, допуская незаконченный черновик.
`inspectScheme` проверяет возможность запуска. Библиотека может содержать пустые переходы;
`schemeSnapshot` внутри разбора должен содержать запускаемую схему.

`status: draft` допускается у корректного графа. Новые схемы и копии имеют статус `draft`;
сохранение готовой/запуск выставляет `ready`, редактирование возвращает `draft`.
`schemeStatus` для старого объекта без `status` выводит готовность из проверки графа:
корректный — `ready`, незавершённый — `draft`. Миграция IndexedDB и смена `FORMAT` не нужны.
При повторном открытии редактора используется `editorNodeId`, если такой блок ещё существует;
иначе стартовый или первый доступный блок. Выбор блока не повышает revision.

Защитные лимиты проверки: 5000 блоков в схеме, 100 вариантов в вопросе, 1000 схем при импорте.
Исполнитель пользовательского графа не использует лимит 20 итераций встроенного алгоритма.
Ограничения длины текстов заданы в валидаторах.

## Снимки и версии

`freshSchemeSession` копирует схему при запуске. Редактирование/удаление библиотеки не меняет
завершённые и незавершённые разборы. Для применения новой версии начать новый разбор.

Для встроенного маршрута сохраняются версия, ответы и заключение, но не полный код алгоритма.
Диспетчера нескольких исторических версий встроенного алгоритма сейчас нет.
При изменении переходов сохранить обработку прежних записей либо подготовить миграцию:
одного повышения `ALGORITHM_VERSION` недостаточно для совместимости.

## Полный экспорт JSON

```json
{
  "format": "entry-navigator/v1",
  "exportedAt": "2026-11-08T00:00:00.000Z",
  "sessions": [],
  "schemes": []
}
```

Архив включает черновики, сделки, наблюдения, изображения, библиотеку и снимки схем внутри разборов.
`currentId`, поиск, фильтры и настройка видимости встроенных примеров в архив не входят.
`editorNodeId` и `status` входят вместе со схемой. `hiddenBuiltinExamples` — локальная UI-настройка:
массив ID `context` / `entry`, отсутствие ключа означает, что оба примера видны.
Удалённые из раздела примеры восстанавливаются кнопкой и не требуют миграции БД.
Браузер создаёт скачиваемый файл через Blob; сервер файл не записывает.
Имя: `entry-navigator-YYYY-MM-DD.json`, дата по локальному времени браузера.

Импорт принимает файл до 100 МБ и до 10000 разборов. Записи проверяет `validateImport`,
библиотеку — `validateSchemes`. Старый JSON без `schemes` принимается.
ID, уже имеющиеся локально, пропускаются целиком: новая версия объекта с тем же ID
не перезаписывает существующий объект. Конфликты по `updatedAt` не разрешаются.
Дубли ID внутри входящего массива считаются ошибкой.

Все объекты проверяются до записи. Само добавление не является одной транзакцией всего файла:
при сбое хранилища часть объектов может уже сохраниться. Повторный импорт пропускает эти ID.
Это добавление отсутствующих данных, а не замена БД.

`SCHEME_FORMAT` экспортируется из `schemes.mjs`, но отдельного экспорта схем с этим форматом нет.
Пользовательский архив использует `FORMAT` из `engine.mjs`.

## Изображения и CSV

Вопрос может содержать `hintImages`, ответ — `exampleImages`: массивы `{id, name, data}`.
В каждой галерее до 10 PNG/JPEG/WebP/GIF по 5 МиБ; `data` — base64 data URL.
ID картинки уникален внутри галереи и сохраняется при замене. Новые изображения получают UUID.
Проверка имени, MIME, base64, размера, количества и ID — в `hint-images.mjs`.
SVG и внешние URL не принимаются. Проверка не является декодером изображения.

Прежние `hintImage` / `exampleImage` с одним объектом `{name, data}` по-прежнему читаются
и проверяются. `imageGallery` показывает их как галерею из одного элемента с ID `legacy`.
Если массив уже присутствует, он имеет приоритет, даже если пуст. Оба поля при импорте
проверяются независимо. Правка вложений записывает массив и удаляет одиночное поле;
простое открытие старой схемы или разбора ничего не перезаписывает.
Версия IndexedDB и формат архива остаются прежними.

Галереи входят в библиотеку, копии схем и `schemeSnapshot`; изменение библиотеки не меняет
начатые разборы. JSON включает все картинки, CSV не содержит изображений.
Из-за копирования в снимки большой файл может присутствовать в архиве несколько раз.

UI журнала допускает до 4 изображений на запись, каждое до 5 МиБ: PNG, JPEG, WebP или GIF.
Они хранятся как base64 внутри записи, увеличивая размер БД и JSON.
Импорт дополнительно проверяет MIME-префикс, base64 и длину data URL.

CSV содержит строки разборов, названия/ID/версии схем и денежные значения.
Полного графа схемы и изображений в нём нет, обратный импорт не поддерживается.
Формат: `;`, UTF-8 BOM, ячейки в кавычках. Начальные символы формул в строках
нейтрализуются апострофом.

## Расчёты

- Винрейт = `wins / (wins + losses)`, округление до десятых процента.
- `closed` включает плюсы, минусы и возвраты; ожидающие исхода исключены.
- Наблюдения без входа не считаются сделками.
- Прибыль закрытой сделки = `payout - stake`, округление до центов.
- Если ставка или полная выплата отсутствует, запись не входит в сумму прибыли.
- При отсутствии подходящих значений API возвращает `null`, UI показывает `—`.

## Изменение формата

Изменение object stores требует повышения версии IndexedDB и миграции в `onupgradeneeded`.
Совместимое дополнительное поле объекта само по себе не требует пересоздания БД.
Менять `FORMAT` вместе с политикой чтения старых архивов и проверками восстановления.
Перед миграцией предусмотреть резервную копию и проверить встроенный разбор, свою схему,
её снимок, черновик и изображения на синтетических данных.
